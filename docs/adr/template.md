# NNNN. Short imperative title stating the decision

- **Status:** Proposed | Accepted | Rejected | Deprecated | Superseded by `[ADR-NNNN](NNNN-title.md)`
- **Date:** YYYY-MM-DD (when the status last changed)
- **Deciders:** who decided, e.g. the owner (omit the line if not recorded)
- **Related:** supersedes, amends, amended by, or partly superseded by `[ADR-NNNN](NNNN-title.md)`; PRDs and issues (omit the line if none)

## Context and problem

What problem or forcing function led to this decision? What was actually observed (a bug report, a user request, a constraint discovered while implementing something else)? Link to the source if there is one.

## Decision drivers

- The constraints, goals, and preferences the choice was judged against.

## Considered options

1. The chosen option
2. Each alternative that was actually considered, including keeping the status quo when that was viable

## Decision outcome

**Chosen option: the chosen option**, because the justification, tied to the decision drivers.

What was decided, stated as plain declarative sentences. Name the concrete files/components this applies to, not just the abstract principle. Number the points when there are several, so a later ADR can supersede one of them.

### Consequences

- **Good:** What becomes easier or safer as a result.
- **Bad:** What becomes harder, or what was given up.
- **Neutral:** Notable changes that are neither.

### Confirmation

How compliance is checked: a lint or dependency rule, a test, the visual suite, a harness, a CI gate, or a review checklist. Write "Not recorded when this decision was made." only for records converted from the old format.

## Pros and cons of the options

Omit this section when only one option was considered.

### Option name

- Good, because …
- Bad, because …

## More information

Links, follow-ups, and when to revisit this decision. Omit this section if empty.
