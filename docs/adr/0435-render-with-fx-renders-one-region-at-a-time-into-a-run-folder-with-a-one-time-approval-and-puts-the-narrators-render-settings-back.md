# 0435. render_with_fx renders one region at a time into a run folder with a one-time approval, and puts the narrator's render settings back

**Status:** Proposed (the worker's choices in building ADR 0306's DAW row, render-encode-master PRD Phase 9; the owner confirms them on #510 with the scripted REAPER pass)
**Date:** 2026-09-28
**Supersedes:** none. It applies [ADR 0306](0306-mastering-is-a-provider-port-and-measurement-stays-one-in-process-judge.md)'s four conditions for the bridge's first render, and is checked in REAPER as [ADR 0066](0066-the-lua-bridge-is-tested-by-a-harness-under-lua-5-4-and-reaper-api-behaviour-is-checked-in-reaper.md) point 5 requires.

## Context

[ADR 0306](0306-mastering-is-a-provider-port-and-measurement-stays-one-in-process-judge.md) made mastering a provider port and declared a `daw` row that renders a region through the project's own track and master FX. It allowed the bridge's first render on four conditions: the narrator approves each render in the UI, it runs only from their action, it is Experimental until the owner's REAPER pass, and it writes only into an empty folder the host made inside the project, never over a file. It left the command's exact shape to the phase that builds it.

Until now the bridge never rendered: `narration_render.lua` sets `RENDER_FILE`, `RENDER_PATTERN` and `RENDER_BOUNDSFLAG` and reads `RENDER_TARGETS`, and the narrator presses Render. The S5 spike ([reaper-spike-s5-render-details.md](../research/reaper-spike-s5-render-details.md)) confirmed action 42230 ("File: Render project, using the most recent render settings, auto-close render dialog") in REAPER 7.80, that `RENDER_TARGETS` predicts the rendered names exactly, and that reading `RENDER_STATS` with a render action's ID can itself trigger a render.

Several choices were open, and the PRD's recommendation (D22) did not settle them:

- how a render names the one region, and how the host tells the file it got;
- whether the Lua checks the approval at all, since a forged command can carry any string ([threat model](../architecture/threat-model.md) row 5a);
- what "a folder the host made inside the project" is, in a form the Lua can check;
- what to do when the narrator's last-used render format is not WAV, which `internal/measure` needs;
- what happens to the narrator's own render settings, which a render has to change.

## Decision

1. **Two commands in `integrations/reaper/narration_master_render.lua`.** `master_chain_read|run` answers `MASTER_CHAIN_FX|run|track|trackName|name|enabled` for each FX slot, every track's in track order and then the master's (track `master`), and `MASTER_CHAIN_READ|run|count|truncated`; it reads and changes nothing. `render_with_fx|run|approval|folder|regions` (regions one per line) answers `FX_RENDER_FILE|run|region|path` per region, in the order asked, and `FX_RENDERED|run|folder|count`, or `ERROR`. The chain list stops at 500 slots and says so, and the host refuses a list that was cut short (`bridge.ErrChainTooLong`): the narrator approves a chain they have seen whole.
2. **Each region renders on its own, as the master mix, between its own bounds.** For each region the Lua sets `RENDER_FILE` to the run folder, `RENDER_PATTERN` to `fx-NN` (never `$region`, so a region's name cannot shape a path), `RENDER_BOUNDSFLAG` to 0 with `RENDER_STARTPOS` and `RENDER_ENDPOS` at the region's bounds, `RENDER_SETTINGS` to 0 (the master mix, so every track's FX and the master's run) and `RENDER_ADDTOPROJ` to 0 (nothing rendered is added to the project), then runs action 42230. A region name that no region has, or that two regions share, is refused before anything renders.
3. **The approval is a one-time token.** The host makes a fresh 128-bit random token for each render from `Request.Approved` and never stores it. The Lua refuses a token that is not 32 to 128 hex characters, and one it has already seen in this REAPER session, even if that earlier command was refused for another reason. This does not stop a forged command (it can invent a new token, as ADR 0306 accepts); it stops a replayed one and makes a host bug that sends no approval fail in the Lua too.
4. **The run folder is `<project>/narration-utils/mastering/<run>`.** The host makes it, empty, for one master (`master-` and 16 hex characters) and removes it afterwards. The Lua refuses a folder that is not absolute, has a `.` or `..` part, does not end in `narration-utils/mastering/<plain name>`, does not exist, or is not empty. Before it renders, `RENDER_TARGETS` must predict exactly one file, `<folder>/fx-NN.wav`, which must not exist; after it renders, that file must exist. The host then refuses any answer that names a file outside the folder, moves the one WAV to the destination with a hard link (which refuses an existing file) or a copy renamed into place once the destination is still free, and measures and judges it with `internal/measure` and `internal/deliveryprofile` only.
5. **A render format other than WAV is refused, not changed.** `RENDER_FORMAT` is the narrator's, stored as REAPER's own encoded sink configuration; writing it would mean shipping a guessed encoding of it. When `RENDER_TARGETS` predicts a file that is not `.wav`, the render is refused with a sentence asking the narrator to choose WAV in REAPER's render settings.
6. **The narrator's render settings are put back.** The seven keys the command writes (`RENDER_FILE`, `RENDER_PATTERN`, `RENDER_BOUNDSFLAG`, `RENDER_STARTPOS`, `RENDER_ENDPOS`, `RENDER_SETTINGS`, `RENDER_ADDTOPROJ`) are read first and written back after the last region, whether the render worked, failed or was refused after the first write. `RENDER_STATS` is never read.
7. **REAPER must not be recording**, as for the transport commands.
8. **Both capabilities are Experimental** for REAPER (`internal/dawport/reaper`), `master_chain_read` gated by `bridge.Actions` like the other experimental commands, and `render_with_fx`'s role handed out by the resolver only while the narrator's settings allow it. The `daw` mastering row is Experimental too: `MasteringChooseProvider` can choose it.
9. **The host does not wire the row to a screen yet.** The row finds the launch's DAW through `masteringport.UseSession`, which nothing sets in this version, so a master with it answers `ErrNoDAW`. The Master & QC flow that shows the chain, asks for the approval and starts a master sets it, together with its binding, schema, golden and mock.

## Consequences

- The harness (`master_render_test.lua`) pins every rule above and 18 mutation checks guard them; the conformance suite gains a fake DAW (`masteringporttest.FakeDAW`) that refuses what the bridge refuses, so every DAW-rendering row is held to the same rules, and a row that trusts a file outside its folder or a DAW's error fails it.
- What only REAPER can show is pending on #510, in a scripted run on a copy of a project with an isolated `-cfgfile`: that action 42230 renders synchronously and closes its dialog; what `RENDER_TARGETS` answers for custom bounds and a plain pattern (the fake predicts `<folder>/<pattern>.wav`); that `RENDER_SETTINGS` 0 runs every track's FX and the master's; the tail (`RENDER_TAILFLAG` is left as the narrator set it); the sample rate and channels; and that the seven keys read back as written. The fake is corrected to match (ADR 0066 point 5).
- A narrator whose last render was MP3 has to choose WAV once in REAPER. If that proves a nuisance, writing a WAV `RENDER_FORMAT` (and putting theirs back) is a later change with its own REAPER check.
- To render without a per-render approval, to render into a folder the host did not make, or to write the narrator's render format, write a new ADR that supersedes this one.
