# 0349. The resume locate reads REAPER's live cursor and items first, and falls back to the saved project, never to a guess

**Status:** Proposed (REAPER's own behaviour of the calls below is an owner check on #510, D65)
**Date:** 2026-09-27
**Supersedes:** none. It delivers [Read Aloud Resume from the DAW](../prds/read-aloud-resume-from-daw.prd.md) Phase 4 on top of [ADR 0231](0231-chapter-track-state-is-one-read-only-answer-of-the-transport-the-arms-the-input-device-and-one-tracks-items.md) (`chapter_track_state`), [ADR 0111](0111-the-resume-point-comes-from-transcribing-the-recorded-tail-and-placing-it-with-the-tracker.md) (the tail locate) and [ADR 0206](0206-resume-reconciles-the-recording-with-the-prompters-last-word-in-the-host-and-asks-only-when-they-disagree.md) (the reconciled verdict). It adds a second source for ADR 0111's "where the recording ends" and changes nothing in how the tail is placed.

## Context

Until now `TeleprompterLocate` read only the saved `.rpp`: the end of the chapter track's last unmuted item, labelled "as of the project's last save". A take recorded but not saved, or the edit cursor the narrator set in REAPER to say "go back to here", never reached it. The PRD's RD2 (the recommendation D22 takes) asks for the live edit cursor when it lies on the track's recorded audio, else the live end of that audio, and the saved project only when REAPER cannot say.

The live read already exists: `chapter_track_state` answers the transport, the edit cursor and the track's items with their active takes (ADR 0231), and the DAW port hands it out as the Track state role (`dawport.TrackStateReader`, capability `track_state`, Experimental until the verification pass). Two things were missing: the live answer did not say whether an item is muted, and nothing turned a cursor on an item into a place in a source file.

## Decision

1. **Live first, through the port.** `TeleprompterLocate` asks the Track state role (`trackStateReaderFrom`, never a concrete adapter) for the chapter's matched or picked track, once per locate, bounded by 3 s. It uses the answer only when it is for the project the app has selected (same `.rpp` path, case-insensitive; a never-saved project never matches). With no role (no DAW, REAPER not reachable, the capability off), a refusal (the track is gone, the Experimental switch), a timeout or another project open, it reads the saved `.rpp` exactly as before. It never mixes the two into a guess.
2. **RD2's place.** Among the track's items that play (a take and a source file, not muted, overlapping the chapter region's span when the match came from a region), the edit cursor is used when it lies after an item's start and no later than its end; when several overlap, the one that starts last, as it plays on top. Otherwise the place is the end of the item that ends last. The source time is the section start (from the saved take of the same GUID, 0 for a take the saved project does not know) + `D_STARTOFFS` + (time − item position) × playrate, and the tail is ADR 0111's 30 s ending there, never before the item's own start in the file.
3. **What only the saved project knows.** A take the saved project has keeps its section start, stretch-marker approximation and source kind (so a MIDI or video take stays unsupported). A take it does not have (a fresh recording) is judged by its file's extension (`.wav`, `.bwf`, `.w64`, `.mp3`, `.flac`, `.ogg`, `.aif`, `.aiff`, `.wv`) and must exist on disk, the same `SourceAvailable` check the `.rpp` reading makes. A relative path resolves against the project folder.
4. **Mute is on the wire.** `TRACK_ITEM` gains a trailing `muted` field (`B_MUTE`), optional in `wire.go`. With an older script that omits it, the saved project's mute for the same item GUID is used, and an item it does not know counts as playing.
5. **Recording runs nothing.** While REAPER records and the chapter's track is armed, the take's file is still growing: the answer is the new status `recording`, with no tail, no placement and a `none` verdict (the last reading is not offered either, as the narrator is recording right now). Recording another track does not stop this track being read.
6. **The answer says where it came from.** The locate result gains `dawSource` (`live` or `saved`) and `dawAt` (`cursor` or `end`), both absent when no track was read, and the verdict's DAW place carries `source: "live"`. The prompt labels a live place "in REAPER now" (the approved `02-disagree` mockup) and a cursor place "Continuing at REAPER's edit cursor". These are additive (a new field, a new status value), so `hostAPIVersion` is unchanged (`docs/architecture/wire-contracts.md` rule 5).

## Consequences

- An unsaved take and a moved cursor now set the resume point, and a stale save no longer does whenever REAPER is reachable with track state on. With it off (the default until the verification pass), nothing changes for the narrator.
- One extra `chapter_track_state` round trip per dialog open (about 50 to 100 ms), and none for a chapter with no track.
- Proposed, for the owner (#510): whether `GetMediaSourceFileName` on a take whose source is a trimmed `SECTION` returns the parent file (the host adds the saved section start only for takes the `.rpp` knows); whether a just-stopped, unsaved take's file is complete enough to decode at once; and whether a take still recording appears as an item before Stop (ADR 0231 already lists that one). Each would change only how a field is filled.
- Reversing this means dropping the live read and the two fields; the saved-project path is untouched and still tested.
