# 0495. A credits row's Check and track link reuse RecordingCheck and mappingConfirm through a synthetic chapter and a credits-aware title lookup

**Status:** Proposed
**Date:** 2026-09-28
**Supersedes:** (none)

## Context

`credits-in-chapter-table.prd.md` Phase 3 was left "partial" ([ADR 0333](0333-a-credits-checks-basis-is-its-rendered-template-text-via-a-synthetic-manuscript-the-sidecar-reads-unmodified.md)): the host's coverage basis for a credits id (`coverage.CreditsChapterID`, `creditsBasis`, `writeCreditsManuscript`) was built and tested, but the Home/Production board's Check button stayed disabled, and ADR 0333 explicitly deferred the UI wiring: "this stream stops at exporting that helper" (`creditsCheckChapter(kind, title)`). This ADR is that follow-up phase.

Two things ADR 0333 assumed would need "no change" turned out to need a small one once actually exercised:

- **The file layout moved.** `stage-navigation-and-page-replacement.prd.md` Phase 2 replaced Home's `AudiobookEstimatePanel.tsx` with `apps/ui/src/components/production/ChapterBoard.tsx`, and the credits rows' disabled-Check text now lives in `CreditsRowPanel.tsx`, a slide-over opened from the board (not an inline table row). The PRD's file list still names the old paths.
- **`ChapterTrackMapConfirm` refuses a credits id.** ADR 0333 said "`evidence.MappingStore` needed no change" for a credits row's track link, which is true of the store itself, but `apps/desktop/mapping.go`'s `mappingConfirm` (the binding `RecordingCheck.tsx`'s in-dialog `TrackLink` calls generically for the `unmapped` reason) rejects any chapter id `chapterTitle` cannot find in `svc.manuscript.Chapters()` — which a credits id, by design (ADR 0150), never is. Confirmed by a failing Go test before the fix: `that chapter is not part of the current manuscript`. The same gate exists in the mock (`apps/ui/src/api/mockHost/chapterTracks.ts`).

## Decision

- **A credits row's Check button opens the same `RecordingCheck` dialog a manuscript chapter's Record cell opens, over a synthetic `ManuscriptChapter`.** `creditsCheckChapter(kind, status)` (`apps/ui/src/components/production/recordingCheckText.ts`) builds `{ id: "credits-<kind>", title, index: 0, wordCount: 0, status, paragraphIds: [{ id: "credits-<kind>-p0", index: 0 }] }` — the one paragraph id matches the host's `creditsParagraphID`, so a reported gap numbers as "paragraph 1" the same way a real chapter's first paragraph would. `RecordingCheck.tsx` itself needed no change (confirmed: it already treats `chapter.id` as an opaque key for every host call). `ChapterBoard.tsx` wires `CreditsRowPanel`'s new "Recording check" button to close the credits slide-over and open `RecordingCheck` as a sibling mount, the same pattern `StageEvidence`'s own status panel already uses for a manuscript chapter. A credits chapter's `openWorkspace` (there is no Proof chapter view for a credits row) and `goToParagraph` (routed to `/script#credits-<kind>` instead of a chapter/paragraph pair) are branched on `creditsCheckKind(chapter.id)`.
- **`chapterTitle` (`apps/desktop/mapping.go`), the one lookup `ChapterTrackSet`, `mappingConfirm` and `chapterTrackUnlink` all validate a chapter id against, now recognizes a credits id first** (`coverage.CreditsKind`), answering the fixed title (`creditsScriptTitles`, already used by the teleprompter) instead of searching `svc.manuscript.Chapters()`. This is the one line ADR 0333's "no MappingStore change needed" claim was missing: the store itself is unchanged, but the binding gating access to it was manuscript-only. The mock's `chapterTrackMapConfirm` gets the same fix, so a credits row's "link a track" flow (the `unmapped` reason's in-dialog fix-it) works identically in both.
- **A credits row's "actual recorded" is the same track-based measurement a manuscript chapter's Recorded column gets** (actual-recorded-column.prd.md, ADR 0193: never an estimate), read by a new binding, `Host.CreditsRecordedLengths` (`apps/desktop/creditsrecordedlengths.go`), rather than through `manuscript.Service`'s own `RecordedLengths` hook (which only ever sees the manuscript's own chapter ids, by construction - a credits id must never enter it). It reuses `recordedLengthsFor` uncached (this binding is read on demand, opening a credits row's slide-over, not on every chapter-list poll the way the manuscript provider is) and the same confirmed-link store a manuscript chapter's own recorded length reads. `useCreditsRows.ts`'s `CreditsRow` gains `recordedSeconds`/`recordedUnavailable`, threaded into `productionFormat.ts`'s `creditsCell` (the board's Recorded column) and `CreditsRowPanel.tsx` (a line in the slide-over), mirroring `boardCell`'s own `UNRECORDED` handling exactly.
- **A credits check's staleness needed no UI work.** `coverage.Service`'s existing `ReasonCreditsChanged`/`ReasonCreditsNotSetUp` (ADR 0333) already flow through `RecordingCheck.tsx`'s generic reason rendering and `recordingCheckText.ts`'s `COVERAGE_REASON_TEXT` map, both wired before this phase; a template edit staling a stored credits result (already proven at the Go layer, `TestACreditsTemplateChangeMarksAStoredResultStale`) now simply becomes visible the moment a credits chapter id flows through the dialog.

## Consequences

- A credits row's recording check is functionally identical to a manuscript chapter's from `RecordingCheck.tsx` down: same dialog, same reasons, same staleness rule, same in-dialog track-link flow. Nothing chapter-specific had to be duplicated for credits.
- The `chapterTitle` fix is narrowly scoped (one function, three call sites) and additive: a manuscript chapter id's behavior is byte-for-byte unchanged (`coverage.CreditsKind` returns `ok=false` for every real chapter id), verified by a Go test that a linked credits track never appears as a manuscript chapter's own recorded length.
- `CreditsRecordedLengths` duplicates one `.rpp` parse `manuscript.Service`'s own cached provider already does when both a chapter list and a credits panel are read in the same window; it does not share `recordedlengths.go`'s `projectParseCache` (an uncached read of a project that is normally already in the OS file cache), which is an accepted simplicity trade for a binding called only when a credits row's slide-over opens, not on every chapter-list poll. A future phase needing tighter latency there can add a shared cache without changing this ADR's decision.
- The board's Check button and Recorded cell for credits rows are the ones that stay: `CreditsRowPanel.tsx`, `ChapterBoard.tsx` and `useCreditsRows.ts`, though outside the PRD's original (pre-move) Phase 3 file list, are the actual location of this UI now that stage-navigation Phase 2 moved it; a future PRD phase updating this area should read this ADR, not the older Phase 2/3 Parallel-session tables' stale `apps/ui/src/components/home/*` paths.
- Track-name suggestions for "Opening credits"/"Closing credits" (`evidence.suggestByMatch`, the PRD's remaining Phase 3 mention) are still not built: no caller constructs a `ChapterCandidate` for a credits id outside the stage engine, which stays manuscript-only by design. That remains open for whichever surface (a Tracks-page suggestion list) needs it.
