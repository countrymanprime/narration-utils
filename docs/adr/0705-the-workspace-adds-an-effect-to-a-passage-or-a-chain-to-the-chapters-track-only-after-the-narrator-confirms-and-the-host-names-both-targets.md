# 0705. The workspace adds an effect to a passage, or a chain to the chapter's track, only after the narrator confirms, and the host names both targets

**Status:** Accepted
**Date:** 2026-09-29

## Context

[ADR 0234](0234-fx-chains-go-on-tracks-and-a-passage-of-a-take-gets-one-plug-in-at-a-time.md) built the REAPER side of applying effects: `add_take_fx` puts one installed plug-in on a split-out passage of a take, and `apply_fx_chain` puts one of the narrator's `.RfxChain` files on a track, each in one undo block. Nothing in the app sent them. Phase 9 of the [edit and proof workspace](../prds/edit-and-proof-workspace.prd.md) is the screen that does: select words in the chapter's script, right-click, choose an effect. That makes the app itself change the REAPER project, so it is a trust boundary (threat model rows 5h and 5p), and it needs a menu the app does not have.

The owner answered the open questions on 2026-09-24 and 2026-09-25: EP9 (ADR 0234: a passage gets one plug-in, a chain goes on a track), EP10 (A: each edit is sent when the narrator confirms it, nothing is queued) and EP16 (A: no delete, cut or mute from the app).

## Decision

1. **The page names words and a choice, never a target.** `WorkspaceAddTakeFX(chapterId, firstToken, lastToken, plugin)` sends a token range. The host resolves it against the chapter's stored alignment, checked against the saved project, to one `bridge.Passage` (item GUID, take GUID, source start and end), exactly as `WorkspaceGoTo` and `WorkspaceLoop` resolve a token (threat model row 5f). `WorkspaceApplyFXChain(chapterId, chain)` sends no track: the host uses the track the chapter's newest check covered (`coverage.Service.ChapterTrackGUID`). The page cannot name an item, a take, a time or a track. `WorkspaceListFX` and the existing `WorkspaceListFXChains` supply the names the menu offers.
2. **One item per request.** A range heard on two items, a word nothing was heard for, an item that is no longer in the saved project, and a range outside the alignment or read backwards are refused by the host with a reason (`crosses_items`, `no_item`, `stale`, `bad_range`) before anything is sent. Multi-item edits stay out (EP16 A, and the PRD's "unless the owner wants them").
3. **Refusals are results, not errors.** `WorkspaceFXResult` is `added`, `applied` or `refused` with a reason and words, and nothing in REAPER changed for a refusal: not connected (`standalone`, `not_running`), `recording`, `stale`, `script_outdated`, `bad_name` (a chain file where a plug-in belongs, or a chain name that is not a plain relative `.RfxChain`), `no_track`, `failed`. The Lua's own refusals (recording, stale, a name the listing does not hold) and the Go client's name checks (`bridge.ErrBadPluginName`, `bridge.ErrBadChainName`) stay the enforcement; the host adds no second copy of them.
4. **Confirm before sending.** The menu only opens a dialog (`ApplyFxDialog`, a `ConfirmDialog`): it names the passage, lists the effects with the narrator's favourites (`DAW.fx_favourites`) first, and says what REAPER will do and that one Undo takes it back. Nothing is sent until the narrator presses Add effect or Put chain on track, and nothing is queued (EP10 A).
5. **A `ContextMenu` primitive** in `apps/ui/src/components/primitives/`, wrapping Base UI's context menu ([ADR 0047](0047-the-ui-primitives-wrap-base-ui-and-app-code-never-imports-it.md)). It is `Menu`'s sibling: the same popup look and keys, opened by a right click, a long press or the Menu key. An item that cannot run stays in the menu, disabled, with its reason under it and as its accessible description. Its popup is portalled into the page's `<main>` instead of `<body>`, so it sits inside a landmark and axe's `region` rule passes without an `axeDebt` entry ([ADR 0064](0064-the-visual-suite-runs-axe-on-every-app-state-and-a-violation-fails-unless-it-is-declared-debt.md)). Its role tree is pinned by an aria snapshot ([ADR 0065](0065-aria-snapshots-pin-the-role-trees-of-the-dialogs-the-slide-over-and-the-navigation.md)).
6. **Selecting a passage** in the script: Shift+click extends from the last word clicked (a plain click still seeks), and a right click on a word outside the selection selects that word. The selection is announced ("3 words selected") and cleared with a button. Selecting on the waveform strip is not built here; the strip has no selection model yet.
7. **No new REAPER command or event.** `wire.go` already holds the five events of these commands (ADR 0234). This decision adds two mutation checks to the existing Lua harness: a chain name the listing does not hold is loaded, and a plug-in is added outside the undo block.

## Consequences

- The narrator can put a de-esser on one sentence, or a chain on the chapter's track, without leaving the app, and one Undo in REAPER takes it back. Both commands stay Experimental behind the DAW port's `fx_chains` capability ([ADR 0230](0230-reaper-commands-built-before-the-verification-pass-are-refused-by-the-host-while-the-experimental-switch-is-off.md), [ADR 0304](0304-bridge-actions-asks-a-per-command-gate-and-the-daw-ports-resolver-answers-it-from-the-per-capability-settings.md)); how REAPER itself behaves (a chain loaded by path, the split's crossfade, one Undo rejoining the pieces) is still for the scripted REAPER run on the owner's machine, which is pending (#510).
- After a split the chapter's stored alignment still names the original item. A second effect on the same words works only while the range lies inside the item REAPER still holds under that GUID; otherwise REAPER answers stale and the narrator is told to run the check again. Following the new pieces is not attempted.
- A chain goes on the chapter's checked track, which is one track. A chapter recorded across several tracks gets the chain on the track of its newest check only.
- The `ContextMenu` primitive is available to the next feature that needs a right-click menu; a new one needs its own story and role-tree snapshot.
- Mute (EP16 B) and delete are not offered. A future decision adds them as new actions on the same menu.
