# 0355. The Merriam-Webster key is sealed in its own per-user file, and the online lookup is a Go-only port with a single-word rule

**Status:** Proposed
**Date:** 2026-09-27
**Supersedes:** none. Implements [ADR 0405](0405-pronunciation-stays-local-first-behind-cmu-wiktextract-and-espeak-with-merriam-webster-as-the-one-narrator-keyed-online-source.md) point 2 (prep depth PRD, [`docs/prds/prep-depth.prd.md`](../prds/prep-depth.prd.md), Phase 9; Open Questions Q10 and Q11, recommendations taken, D22) and records where the implementation departs from the letter of Q10 and the PRD's Technical Approach, and why. Proposed, not Accepted, because three of those departures are the owner's to confirm (Consequences, last bullet; #510).

## Context

ADR 0405 decided that Merriam-Webster is the one pronunciation source that fetches: on the narrator's own key, one word at a time, cached, never logged. It left the shape of the code to Phase 9. Four facts from the code shaped it:

- **The Go `pronunciationport` registry is shared with Python.** Its rows (`cmu`, `espeak`) are sources the Story Bible sidecar runs; the packaged smoke test requires the sidecar's own `capabilities` report to name every Go row (`smoke.go`, `checkGuideCapabilities`), `ProviderCapabilities` shows every row on the providers page, and `FallbackOrder` is the sidecar's build-time fallback. Merriam-Webster runs in the Go host, not the sidecar, and must never be part of the offline fallback.
- **Settings are plain JSON the app copies and reads back.** `internal/settings/store.go` keeps every value as clear text per user and per project, and a project's settings file travels with the project.
- **The Story Bible's pronunciation entries are written by the sidecar** (`pronounce`, `pronounce-user`, ADR 0346). Writing an online answer into an entry would be a new sidecar command and a new `source` value on the Python side, which Phase 8 (Wiktextract, a separate stream) is also changing.
- **Wails logs every binding call's arguments at Debug** (`messageprocessor_call.go`, "Binding call complete ... args"). The app leaves Wails at its default level (Info) and sets no logger of its own, so this is silent today, but the one binding that takes the key would print it if that ever changed.

## Decision

1. **The online role is a Go-only port, beside the shared registry, not a row in it.** `internal/pronunciationonline` holds the port (`Dictionary`: `Name`, `Label`, `Host`, `SignUpURL`, `Notation`, `Lookup(ctx, word, key)`), the privacy rule, the cache and the key; its one adapter is `internal/pronunciationonline/merriamwebster`, the only package in the host's pronunciation code that imports `net`, and the only fourth row in `.golangci.yml`'s `depguard` allow-list (its parent package stays fenced). The fake in `pronunciationonlinetest` is what the tests, the goldens and the privacy tests run against (D67). The composition root (`bindings_pronunciationonline.go`) is the only file that builds the adapter; `pronunciationonlineguard_test.go` fails any other importer of the adapter or of `credentialstore`, and any other file that names an address on `dictionaryapi.com`. `pronunciationport`'s rows, `FallbackOrder` and the sidecar's `capabilities` report are unchanged, so the offline chain cannot reach the network by construction.
2. **The key lives in its own per-user file, not the settings file** (a departure from Q10's "an opaque blob in the per-user settings file"): `%APPDATA%\narration-utils\credentials.json`, owned by `internal/credentialstore`, written whole through a temporary file and a rename, mode 0600, beside the settings and recents but outside `logs\`. On Windows (the supported platform, D74) each value is sealed with `CryptProtectData` (current-user scope, `CRYPTPROTECT_UI_FORBIDDEN`, an app-specific entropy) through `golang.org/x/sys/windows`, already a dependency; elsewhere it is kept in the clear and `ProtectedAtRest` tells the Settings page to say so. A separate file keeps the key out of anything that reads, copies or exports settings, and keeps `internal/settings` (a serial point) unchanged.
3. **A secret never prints.** Inside the host the key is a `credentialstore.Secret` whose every text form (`fmt`, `%#v`, JSON, text, `slog`) is `[redacted]`; only `Reveal`, called in the adapter's request builder, gives the value. No error in the port, the store or the adapter carries the key or the word: a transport error is replaced by a fixed sentence (Go's `*url.Error` would quote the URL, key included), a damaged file is reported without its content, and a refused paste is not echoed. Redirects are never followed. The status binding returns only `present` and `protectedAtRest`, with a `strict` Zod schema. `TestTheAppNeverLowersWailsLogLevel` fails if `main.go` ever sets `application.Options.LogLevel` or `Logger`.
4. **"A single word" is a checked rule, the same on both sides of the boundary** (Q11): `pronunciationonline.CheckWord` accepts the name or alias the narrator is looking up, at most three space-separated parts and 64 characters, made of letters, marks, digits, apostrophes, hyphens and periods, and refuses anything else (a sentence, a line break, a path, a file name, an id) before any request. `apps/ui/src/pronunciationOnlineWords.ts` is the same rule for the batch notice and the mock; both are tested against the same cases.
5. **A batch is confirmed by its count.** `LookupBatch(words, confirmedCount)` refuses, before sending anything, a batch whose distinct word count (case-insensitive) is not `confirmedCount`, so the notice the narrator agreed to ("Look up 13 names online?") and the request are counted by one rule; at most 200 words; a refused key, the rate limit or a lost connection stops it. A single press needs no dialog.
6. **The cache is its own per-user file, not the Story Bible entry** (a departure from the PRD's "beside the existing pronunciation entry"): `%APPDATA%\narration-utils\pronunciation\merriam-webster-cache.json`, keyed by the lower-cased word, answers only (never the key), at most 5000, oldest dropped first. A cached word is answered without unsealing the key and without a request, offline included; a not-found answer is cached too; a failed lookup is not. Keying by word rather than by project means a name looked up for one book is not sent again for the next.
7. **An answer is offered, not stored as a source.** Merriam-Webster gives its own respelling (for example `\krō-ˈkā\`), not IPA, so the UI labels it "Merriam-Webster respelling" and **Use this** only fills the narrator's own pronunciation field; the narrator saves it with the existing **Use mine** (ADR 0346's `user` source, the dictionary's answer kept as the alternate). No new `source` value reaches the sidecar or the Story Bible file in this phase.
8. **The UI.** Settings > Story Bible (Global scope) holds the key: **Get a free key** opens the adapter's fixed sign-up page through the same trusted-URL path as the browser lookups, a masked field (`Field`'s new `secret` mode: `type=password`, autofill and spell check off) takes the paste, and **Remove key** deletes it. The Story Bible's pronunciation details gain **Look up online** (one press, one word, no dialog), and the Pronunciation queries slide-over gains **Look up online…**, which opens the batch notice.

## Consequences

- **Easier:** the privacy rule is code with tests, not a convention: the request's exact contents, the word rule, the batch count, the cache-before-request order and "neither the key nor the word is in any log" each fail a test when broken (`merriamwebster_test.go`, `service_test.go`, `credentialstore_test.go`, `bindings_pronunciationonline_test.go`, `pronunciationonlineguard_test.go`).
- **Easier:** Phase 8's offline chain and this phase share no code path, so neither can make the other reach the network, and neither blocks on the other.
- **Harder:** a second place holds per-user state (`credentials.json`) that a future "reset the app" or "move to a new machine" feature must know about; a DPAPI-sealed key does not move to another Windows account or machine, and the narrator pastes it again.
- **Harder:** answers are not in the Story Bible file, so another computer, or a restored project, starts with an empty cache; the narrator's chosen pronunciation, once saved with **Use mine**, is in the Story Bible as usual.
- **For the owner (#510):** (a) confirm the key file instead of Q10's "in the per-user settings file"; (b) confirm the cache file keyed by word instead of an entry in the Story Bible, and whether a "Clear online answers" control is wanted; (c) confirm that Merriam-Webster's current API terms allow caching answers locally and what attribution they ask for, and check the sign-up URL, endpoint and response shape against the live service, which this session's egress proxy could not reach ([Phase 0 note](../research/merriam-webster-api.md)). Any of these changing is a new ADR that supersedes the point it changes.
