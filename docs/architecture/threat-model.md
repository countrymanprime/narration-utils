# Threat model

**Status: reviewed 2026-10-18.**
**Keeping it true.** A change that touches a trust boundary below updates this file in the same pull request: the `feature-cleanup` skill and the pull request template both ask "does this add or change a trust boundary, a privilege or what the app sends off the machine?". A file the app writes and reads back for the same user is listed in [data files](../reference/data-files.md), not here, unless it names a path the host opens, a command it runs or a URL it fetches. Bump the date above when a row is re-read against the code. Do not log changes here; the history is `git log -p docs/architecture/threat-model.md`. A finding that is not fixed here is a GitHub issue ([Tracking work on GitHub](../operations/github-workflow.md)), named in its row.

## How to read it

| Letter | Threat | | Letter | Threat |
| --- | --- | --- | --- | --- |
| S | Spoofing: pretending to be a server, a file or a process | | I | Information disclosure |
| T | Tampering: changing bytes in transit or at rest | | D | Denial of service |
| R | Repudiation: no record of what happened | | E | Elevation of privilege |

The attacker is one of: **a network attacker** (or a compromised server) between the app and GitHub or Hugging Face; **a hostile file** the narrator opens (a manuscript, a REAPER project, an archive); **another process of the same Windows user** (there is no privilege boundary between two programs a person runs, so this is a fact to record, not a fight to win); **the supply chain** (a dependency or a workflow change that reaches a release). Local-first is the design: the narrator's manuscripts, audio and Story Bible stay on their machine, and nothing here assumes a server of ours, because there is none.

The boundaries are drawn in the [container view](codebase-map.md#how-the-parts-connect), and the four flows that cross them are drawn step by step beside the doc that owns each: [the first-use download](first-use-dependency-provisioning.md#the-install-step-by-step), [a live teleprompter session](manuscript-teleprompter.md), [a REAPER bridge command](reaper-bridge.md#one-command-step-by-step) and [the whole update](in-app-update.md#the-whole-update-step-by-step) (each names the row of this model that a step answers).

## What is protected

| Asset | Where it lives | Why it matters |
| --- | --- | --- |
| Manuscripts, the Story Bible, notes | the project's `narration-utils/` folder next to the REAPER project | unpublished writing of the narrator or the author |
| Recorded audio and the `.rpp` project | the narrator's folders, read (never modified) by the app; REAPER edits the project through the bridge. The Booth's built-in recorder (rows 4g and 4h, Experimental) writes **new** take files into the project's `Recordings` folder but never modifies, overwrites or deletes an existing one | the product being made |
| Settings, recents, host log, run log | `%APPDATA%\narration-utils` and the per-user cache | small; the host log records where data went wrong and never what the data was ([`hostlog`](../../apps/desktop/internal/hostlog/hostlog.go)); the run log (`logs/run.jsonl`, `logs/runs/*.stderr.jsonl`) records the same way for every tool run ([Reading a run](../operations/verification-tooling.md#reading-a-run)) |
| The narrator's Merriam-Webster key, and the online answers | `%APPDATA%\narration-utils\credentials.json` (the key, sealed with DPAPI for the current Windows user) and `pronunciation\merriam-webster-cache.json` (answers, keyed by the looked-up word) beside it, both outside `logs\` | the key is the narrator's own account at Merriam-Webster; the cache lists names from the narrator's books (row 13) |
| Downloaded models, voices and the dictionary | `%LOCALAPPDATA%\narration-utils\assets` | a wrong model gives wrong text, and a weight file is parsed by native code; the dictionary's dataset is parsed, and its lookup index read, by the Go host itself |
| The program itself | the install folder, replaced in place by the update | code that runs with the narrator's rights |
| The release | GitHub Releases | what every narrator installs |

## What the app sends off the machine

The statements below are the ones the docs make elsewhere; each is checked by something that fails.

- **No telemetry, no analytics, no crash upload, no account.** Nothing in the host or the UI reports usage. The host log stays on disk (`hostlog`, [Wire contracts: how data is checked where it crosses a boundary](wire-contracts.md)); analyzers report findings and never upload them ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md)).
- **No listener.** The desktop host opens no port and no socket. The `/media` route is the Wails asset server's in-process handler, reached only by the app's own webview; so are the page's binding calls and events on Wails v3, which are requests to `/wails/runtime` on `http://wails.localhost` that WebView2 hands to the host in-process (`WebResourceRequested`), and v3's server mode, the only one that listens on a port, is behind a `server` build tag the build never sets ([ADR 0001](../adr/0001-the-app-is-written-in-go.md)); the REAPER bridge is files in a folder ([The DAW port](daw-integration.md#the-daw-port)).
- **The Go host imports networking in four places only:** `internal/assets` (first-use downloads), `internal/update` (the app's own update), the root `media.go` (the local route) and `internal/pronunciationonline/merriamwebster` (the narrator-keyed online dictionary, row 15; its parent package, which holds the key and the cache, stays fenced). A `depguard` rule in [`.golangci.yml`](../../apps/desktop/.golangci.yml) fails the lint on any other import of `net`, `crypto/tls` or `golang.org/x/net` ([ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md) point 4). The fence does not see a sidecar's own network use, which is why the sidecars are loaded from a verified local directory (row 1).

Every outbound request the shipped app can make:

| Request | When | Carries | Off switch |
| --- | --- | --- | --- |
| `GET api.github.com/repos/countrymanprime/narration-utils/releases` | automatically once a day at most (2 hours after a failed check), 12 s after the window is up, and when the narrator presses **Check now** (row 2) | the program name and version in `User-Agent`, an `ETag`; nothing about the narrator, the project or the machine | Settings > About & updates > `Updates.check_on_startup` |
| Hugging Face and GitHub asset downloads | only after the narrator confirms an install (row 1) | the file path of one pinned URL | not started without a click |
| The update download from GitHub Releases | only after two clicks (row 2) | the URL of one release asset | not started without a click |
| `GET www.dictionaryapi.com/api/v3/references/collegiate/json/<word>?key=<key>` | only when the narrator presses **Look up online** for a name this computer has not looked up before, (row 15) | the one looked-up word or short name and the narrator's own key; Go's generic `User-Agent`; no cookie, referer, body or header of the app's own | no key saved, no request; **Remove key** in Settings > Story Bible |

A developer running a sidecar by hand with a model *name* instead of `--model-dir` makes `faster-whisper` download from Hugging Face by itself (`sidecars/transcript-compare/core/compare.py`, `sidecars/manuscript-teleprompter/core/live_asr.py`, `local_files_only=bool(model_dir)`), and the Moonshine engine of the teleprompter sidecar, run from source, lets the `moonshine-voice` library download its model from Moonshine's servers when it is given no `--model-dir`. The frozen sidecar that ships cannot: it refuses to run Moonshine without a `--model-dir` and checks that directory holds every file the catalog pins, word-timestamp decoder included (`sidecars/manuscript-teleprompter/core/moonshine_engine.py`, [Manuscript Teleprompter](manuscript-teleprompter.md); the host passes it the verified catalog directory of whichever engine the narrator chose). The mock-API bundle of the UI (`VITE_USE_MOCK_API=1`, development, the visual suite and the public demo) makes no request either: its sample manuscript, the Project Gutenberg text of *Alice's Adventures in Wonderland*, ships with the bundle (`apps/ui/src/api/fixtures/`, loaded by `aliceManuscript.ts`). The app never does: the host resolves the model directory from an installed, verified catalog entry and refuses with `asset_required` otherwise (`apps/desktop/bindings.go`). The start-up test `apps/desktop/startup_offline_test.go` replaces the HTTP transports with ones that fail, and asserts that opening the app, choosing a model and reading the catalog make no request except the update check, and that one only to the releases address and only when it is switched on.

### 2. The app's own update (`SECURITY.md` bullet 3)

Boundary: GitHub's API and CDN to the app, which then replaces its own executable ([in-app update](in-app-update.md), [ADR 0002](../adr/0002-local-models-and-tools-come-first-so-the-app-is-free-to-use.md) to [The install and the rollback](in-app-update.md#the-install-and-the-rollback)). This is the boundary where a mistake runs an attacker's program with the narrator's rights, so it has the most rows.

### 14. The Audacity scripting pipe (`SECURITY.md` bullet on the Audacity pipe; new boundary)

Boundary: the Go host writes scripting commands to Audacity's `mod-script-pipe` and reads its replies, over two local named pipes (`\\.\pipe\ToSrvPipe`, `\\.\pipe\FromSrvPipe`) that Audacity 3.x creates once the narrator enables the module in Preferences > Modules; Audacity 4.0 creates none ([The DAW port](daw-integration.md#the-daw-port), [the published spec](../research/audacity-4-scripting-spec.md); `apps/desktop/internal/audacitybridge`). ### 15. Merriam-Webster online pronunciation lookup (`SECURITY.md` bullet 13; new boundary)
