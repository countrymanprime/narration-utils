## UI changes are gated by the visual suite and the component atlas

A change under `{{UI_ROOT}}/src` is not done until, from `{{UI_ROOT}}`: the unit tests (which also run every story), lint, and build pass, `{{PM_RUN}} screenshots` (app states) passes, and `{{PM_RUN}} atlas` (every story x light/dark x wide/narrow, with axe) passes. Then open the generated PNGs for every viewport - green cannot tell you a layout looks right.

- A new or changed component needs a `<Name>.stories.tsx` next to it (`src/atlasCoverage.test.ts` fails otherwise).
- A run that goes red gets fixed in the UI or the driver. `sameAs`, `undriven` and `tests/atlas/a11y-debt.ts` entries are escape hatches that need a real reason and may only shrink.
- Screenshots are gitignored scratch output; `docs/ui/` is generated by `ui-atlas docs`.
