# UI Atlas kit: design

A reusable way to test and self-document React UIs through a visual component library, extracted from the
working implementation in `shared/ui` of this repo (see `docs/adr/0021-visual-suite-capture-contract-and-storybook.md`).
It ships as one Claude Code plugin (`plugin/`) that is self-contained: skills, agents, commands, hooks, a CLI and
the templates the CLI copies into a consuming repo.

## What problem it solves

Visual tests that run only when someone remembers, give different pictures on identical code, skip states
silently, and are judged by eye, do not protect a UI. The kit makes the visual layer a *gate* that runs in CI,
and makes the component library the repo's living documentation (`docs/ui/`), readable by people and agents.

## Layers (a consuming repo picks a tier)

| Tier | Contents | For |
| --- | --- | --- |
| 0 | App page-state capture: `tests/visual/` (catalog + drivers + generic runner + validators) | Small sites with a few pages |
| 1 | Tier 0 + Storybook atlas of the primitives (`.storybook/`, `*.stories.tsx`, `tests/atlas/`) | Any repo with a shared component set |
| 2 | Tier 1 + generated docs (`docs/ui/`), coverage ratchets, CI jobs, hooks | Repos where the library is the product surface |

## Folder structure in a consuming repo

```
<ui-root>/                          # e.g. shared/ui, src/, or the repo root
  .storybook/{main.ts, preview.tsx, preview-head.html}
  playwright.config.ts              # app capture (tier 0+)
  playwright.atlas.config.ts        # atlas capture (tier 1+)
  src/components/<...>/<Name>.stories.tsx   # a story is the catalog entry and its driver
  src/atlasCoverage.test.ts         # every primitive has a story or a reasoned exemption; debt ratchet
  src/stories.test.tsx              # every story runs as a unit test (composeStories)
  src/visualSuite.test.ts           # catalog integrity + validators (tier 0+)
  tests/visual/{app.spec.ts, app.drivers.ts, state-catalog.ts, viewports.ts, global-setup.ts, lib/, helpers/}
  tests/atlas/{atlas.spec.ts, a11y-debt.ts}
docs/ui/{atlas/*.md, inventory.json, images/}     # generated by `ui-atlas docs` (tier 2)
ui-atlas.config.json                # detected settings + kit version stamp
```

## The capture contract (what makes the output trustworthy)

1. One test per `{page, state, viewport}` (app) or `{story, theme, viewport}` (atlas). No retries.
2. Conditions, never sleeps. Timers are frozen only in the one state that needs it, never page-wide.
3. Fails on: page error, failed request, console.error, sideways overflow, blank image, axe violation, a throwing
   `play()`, and two states that render byte-identically unless a catalog row declares `sameAs` (checked).
4. No silent skips: a row with no driver needs an `undriven` reason and the count can only shrink.
5. Known problems are explicit debt (`tests/atlas/a11y-debt.ts`: rule, reason, count ratchet), never hidden.
6. Duplicates are found by exact bytes; a coarse signature only forgives anti-aliasing jitter on declared pairs.
7. Baselines (pixel diffs) are only ever produced in a pinned Linux container, never on a developer machine.

## Test-depth rubric

Primitive (variants/state logic, or 2+ consumers): full variant x state x theme matrix, keyboard/focus, axe,
one wide and one narrow viewport. Composite: representative states, 2 viewports. Feature/page: state catalog
through real interaction at every viewport. Skip (`atlas-exempt` with a reason): pure layout wrappers,
single-use glue, third-party re-exports.

## CLI (`plugin/cli/ui-atlas.mjs`, Node >= 20, no dependencies)

| Command | Does |
| --- | --- |
| `init [--dir <ui-root>] [--tier 0\|1\|2] [--dry-run]` | Detect stack (package manager, React, Vite, Tailwind, TS, Playwright/Vitest), write templates, add package.json scripts, write `ui-atlas.config.json`. Never overwrites an existing file; reports what it skipped. |
| `audit [--dir] [--json]` | Read-only scorecard 0-100: components vs stories vs exemptions, undriven/`sameAs`/debt counts, CI jobs present, generated docs freshness, kit-file drift. Exit 1 below `--min` (default 0). |
| `docs [--dir]` | From `storybook-static/index.json` and `screenshots/atlas/`, write `docs/ui/atlas/<Component>.md`, `docs/ui/inventory.json` and compressed images. |
| `sync [--dir] [--check]` | Compare vendored kit files in the consumer with the plugin templates; `--check` exits 1 on drift, otherwise refreshes them. |

## Plugin contents

Skills (single trigger each): `ui-atlas-init`, `ui-component-inventory`, `ui-story-authoring`, `ui-state-catalog`,
`ui-capture-contract`, `ui-visual-review`, `ui-atlas-docs-sync`, `ui-atlas-ci`, `ui-atlas-gate`.
Agents: `ui-atlas-auditor` (read-only scorecard), `ui-story-writer` (parallel per component batch),
`ui-visual-reviewer` (independent of the implementer), `ui-flake-doctor`, `ui-atlas-rollout` (orchestrator).
Commands: `/ui-atlas:init`, `/ui-atlas:audit`, `/ui-atlas:sync`, `/ui-atlas:review`.
Hooks: PostToolUse marks UI files dirty; Stop warns when UI changed and no gate evidence exists.

Every skill and agent must reference real commands and real files of the implementation, not aspirational ones.
